## 一、API 响应时间

| 接口 | 方法 | 耗时 | 状态 | 说明 |
|------|:----:|:----:|:----:|------|
| `/health` | GET | **7.2ms** | ✅ 200 | 健康检查，快速 |
| `/api/server/status` | GET | **1007.0ms** | ✅ 200 | 实时采集系统指标（CPU/内存/磁盘） |
| `/metrics` | GET | **7.7ms** | ✅ 200 | Prometheus 指标端点 |
| `/api/auth/login` | POST | **267.9ms** | ✅ 200 | bcrypt 密码验证 + JWT 签发 |
| `/api/auth/me` | GET | **5.0ms** | ✅ 200 | JWT 解析 + 用户查询 |
| `/api/conversations` | GET | **5.3ms** | ✅ 200 | 数据库查询，带 JWT 认证 |
| `/api/knowledge` | GET | **5.0ms** | ✅ 200 | 数据库查询，带 JWT 认证 |

### 统计

| 指标 | 数值 |
|------|:----:|
| 平均响应时间 | **186.4ms** |
| 中位响应时间 | **7.7ms** |
| 最快接口 | `/api/auth/me` (5.0ms) |
| 最慢接口 | `/api/server/status` (1007.0ms) |
| 排除系统指标采集后平均 | **49.7ms** |

### 分析

- **轻量接口**（健康检查、JWT 验证、数据库查询）：5~8ms，性能优良
- **登录接口**（267.9ms）：bcrypt 密码哈希运算为计算密集型，属正常范围
- **系统指标采集**（1007.0ms）：首次调用 `psutil` 采集 CPU/内存/磁盘，含磁盘 IO 统计，属正常范围；缓存后二次调用将显著降低

## 三、内存占用

| 进程 | 内存占用 | 说明 |
|:----:|:--------:|------|
| Python (uvicorn) | ~150 MB | 主后端进程（含 FastAPI、LangGraph、依赖库） |
| Python (其他) | ~30 MB × 2 | 辅助 Python 进程 |
| 总计 | ~210 MB | 开发环境内存占用 |

### 分析

- 主进程 150MB：含完整 Python 运行时 + FastAPI + LangGraph + SQLAlchemy + 所有工具依赖
- 内存占用合理，未发现泄漏（多次请求后内存稳定）
- 生产环境建议配置容器内存限制为 512MB

## 四、总结

| 维度 | 评估 | 说明 |
|------|:----:|------|
| API 响应速度 | 🟢 **优秀** | 平均 186ms，核心业务接口 <10ms |
| 数据库性能 | 🟢 **正常** | 查询 5ms 级别，连接池无泄漏 |
| 内存占用 | 🟢 **合理** | 主进程 150MB，符合 Python 应用预期 |
| 慢接口识别 | 🟡 **需注意** | `/api/server/status` 首次调用约 1s，建议前端加 loading |

> **建议**：
> 1. 对 `/api/server/status` 实现指标缓存（~5s 过期），避免每次实时采集
> 2. 生产环境配置 PostgreSQL 连接池大小根据并发量调整
> 3. 生产环境需配置内存上限（容器 512MB / 物理机 1GB）
