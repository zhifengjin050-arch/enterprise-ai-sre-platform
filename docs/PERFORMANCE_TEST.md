## 2. Agent 调用时间

| 场景 | 总耗时 | LLM 推理占比 | 工具调用占比 |
|------|--------|-------------|-------------|
| 场景 1：服务器健康检查 | **35,988ms** | 29,985ms (83.3%) | 5,187ms (16.7%) |
| 场景 2：订单服务故障分析 | **89,816ms** | 44,219ms (49.2%) | 45,597ms (50.8%) |

> **说明**：
> - LLM 推理耗时 ≈ DeepSeek-V4-Flash API 往返时间（含生成延迟）
> - 场景 2 耗时较长因为涉及 13 个工具调用（包括 Docker/K8s/SSH 等超时工具）+ DeepSeek 生成长报告
> - SiliconFlow DeepSeek-V4-Flash 首次调用偏慢（cold start），后续调用会更快

## 3. 性能数据分析

### 耗时分布

```
普通 API:  ■■■■■■■■■■ 5-19ms (极快)
MCP 工具:  ■■■■■■■■■■ 0-500ms (大多数)
MCP 进程:  ■■■■■■■■■■■■■■■■■■ 1,500ms (list_processes)
Agent + LLM: ■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■ 30-44s (LLM推理)
```

### 瓶颈识别

| 组件 | 瓶颈级别 | 说明 |
|------|---------|------|
| DeepSeek-V4-Flash API | 🔴 高 | 单次推理 15-30s，长报告 44s |
| list_processes | 🟡 中 | psutil 采集需遍历所有进程 |
| k8s_get_pods | 🟡 中 | K8s API 调用超时等待 |
| 其他 API | ✅ 低 | 均 < 50ms |

## 4. 结论

| 指标 | 值 | 判定 |
|------|-----|------|
| 普通 API 平均响应 | 14ms | ✅ 优秀 |
| API 最大响应 | 27ms | ✅ |
| Agent 平均耗时 | ~60s | ⚠️ 含 LLM 推理 |
| Agent 工具调用效率 | ~30s | ⚠️ MCP stdio + 远程调用 |
| 错误率 | 0% | ✅ 所有请求成功 |
