# 以证据为中心的智能故障诊断 · 工程导读

将故障描述转成分步诊断，结合基础设施现场信息与知识库，输出可追问、可核查的故障报告。

## 先理解核心流程

```mermaid
flowchart LR
  N0["故障描述"]
  N1["Agent 规划"]
  N2["MCP 现场采集"]
  N3["知识与记忆"]
  N4["结构化报告"]
  N0 --> N1 --> N2 --> N3 --> N4
```

## 值得深入的设计

- LangGraph 循环负责多步推理与工具调用；重点阅读每步如何结束、继续和处理错误。
- 现场信息与 Runbook 解决不同问题：前者描述当前状态，后者提供排查知识，报告应明确证据来源。
- SSE 面向执行进度展示，Trace 面向事后分析，两者共同支持诊断过程可见。

## 一次演示应验证什么

1. 启动脚本检查 /health 或 /api/health，随后运行 demo/import_demo_data.py；需准备宿主机 Python 与导入依赖。
2. 先从只读场景开始：选择一个测试命名空间中的 Pod 故障，检查工具参数和返回证据。
3. 确认流式输出、调用耗时和最终报告能对应同一次诊断，不将示意截图当作环境验收。
