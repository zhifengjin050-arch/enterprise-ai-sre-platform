## 2. 架构变化

### 原架构 (v2.0.0)

```
用户 → FastAPI → LangGraph Agent → RAG / Memory / LLM / Tool Router / MCP
```

### 新架构 (v2.1.0)

```
用户 → FastAPI
  ├── POST /api/chat (同步, 保持不变)
  │
  ├── POST /api/chat/stream (新增 SSE 流式)
  │     → SSE 实时推送 (thinking → RAG → Memory → LLM → Tool Call → 结果)
  │
  ├── GET /api/agent/traces/{id} (新增 Trace API)
  │     → 完整执行链路查询
  │
  └── LangGraph Agent (增强)
        → _stream_id 注入 (实时事件推送)
        → RAG / Memory / LLM / Tool Call 全过程可观察

新增: streaming 模块 + trace 模块
增强: agent 节点 + tools 节点 (事件推送)
新增: Demo 模式 (DEMO_MODE=true)
新增: 前端 /trace 页面 (LangSmith-like Timeline)
```

## 3. 新增功能详解

### 3.1 Agent Streaming 实时输出

| 特性 | 说明 |
|------|------|
| 端点 | `POST /api/chat/stream` |
| 协议 | Server-Sent Events (SSE) |
| 事件列表 | `agent_start`, `thinking`, `rag_search`, `memory_load`, `llm_start`, `tool_call`, `tool_result`, `final_answer`, `complete`, `error` |
| 兼容性 | 不影响已有的 `POST /api/chat` 同步接口 |
| 实现方式 | 通过 `_stream_id` 注入 AgentState，在 agent 节点和 tools 节点中插入事件推送 |

**事件流示例：**

```
data: {"type":"agent_start","content":"Agent 开始分析用户需求..."}

data: {"type":"rag_search","query":"服务器 CPU 异常","status":"running"}

data: {"type":"rag_search","query":"服务器 CPU 异常","status":"completed","result_count":2}

data: {"type":"memory_load","type":"long_term","status":"running"}

data: {"type":"memory_load","type":"long_term","status":"completed","failures":1,"solutions":2}

data: {"type":"llm_start","model":"deepseek-ai/DeepSeek-V4-Flash","status":"running"}

data: {"type":"llm_start","model":"...","status":"completed","duration_ms":3850}

data: {"type":"tool_call","tool":"get_cpu_usage","status":"running","args":"{}"}

data: {"type":"tool_result","tool":"get_cpu_usage","status":"completed","result":"CPU: 45%"}

data: {"type":"final_answer","content":"## 服务器健康报告..."}

data: {"type":"complete","content":"Agent 执行完成"}
```

### 3.2 Agent Trace 执行轨迹系统

| 特性 | 说明 |
|------|------|
| 数据模型 | `AgentTrace` (agent_traces 表) |
| 字段 | id, conversation_id, step, event_type, content, tool_name, duration, meta_info, created_at |
| 保存步骤 | 用户请求 -> Agent分析 -> RAG检索 -> Memory读取 -> LLM调用 -> 工具调用 -> 工具结果 -> 最终输出 |
| API | `GET /api/agent/traces/{conversation_id}` |
| 返回格式 | `{ steps: [{event, content, tool, duration, meta}] }` |
| 前端页面 | `/trace` — 时间线可视化，类似 LangSmith |

### 3.3 企业 Demo 模式

| 特性 | 说明 |
|------|------|
| 配置文件 | `docker-compose.demo.yml` |
| 环境变量 | `DEMO_MODE=true` |
| 不依赖 | 真实服务器、Docker、Kubernetes |
| 适用场景 | 克隆项目后立即体验、面试展示、产品演示 |
| 三个 Demo | ① 服务器CPU异常诊断 ② 订单服务故障分析 ③ Grafana截图分析 |

### 3.4 前端 Trace 页面

| 特性 | 说明 |
|------|------|
| 路由 | `/trace` |
| 功能 | 输入 conversation_id 查看执行轨迹；发送测试消息触发 Agent 执行并查看轨迹 |
| 可视化 | 时间线 + 事件类型彩色徽标 + 耗时显示 + 详情展开 |

## 5. 使用方式

### 体验 Streaming

```bash
curl -X POST "http://localhost:8000/api/chat/stream" \
  -H "Content-Type: application/json" \
  -d '{"message":"检查服务器CPU状态"}' \
  --no-buffer
```

### 查看 Trace

```bash
# 1. 发送消息获取 conversation_id
curl -X POST "http://localhost:8000/api/chat" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"message":"检查服务器状态"}'

# 2. 查询执行轨迹
curl "http://localhost:8000/api/agent/traces/{conversation_id}" \
  -H "Authorization: Bearer <token>"
```

### 启动 Demo 模式

```bash
docker compose -f docker-compose.demo.yml up -d
```

### 前端访问

- 主页面: `http://localhost/dashboard`
- AI 对话: `http://localhost/chat`
- Trace 轨迹: `http://localhost/trace`
- 知识库: `http://localhost/knowledge`
