# Enterprise AI SRE Operations Console v3.2.0 — 升级报告

> **生成时间**: 2026-08-18  
> **版本定位**: 在 v3.0/v3.1 生产后端之上，把产品从「功能后台」升级为 **Enterprise AI SRE 控制台**  
> **Demo 登录**: `webtest` / `webtest123`  
> **前端**: http://localhost:5173　**后端**: http://localhost:8000

---

## 1. 升级概览

| 维度 | v3.1.0（Production） | v3.2.0（SRE Console） |
|------|----------------------|------------------------|
| **产品形态** | API + 分散页面 | 企业 SRE 工作台（总览 / Copilot / 事件 / 基础设施 / 知识 / 轨迹 / 监控） |
| **信息架构** | `/dashboard` `/chat` `/servers` `/trace` | `/overview` `/ops` `/incidents` `/infra` `/knowledge` `/traces` `/monitor`（旧路径 301 到新 IA） |
| **总览** | 多接口拼装 | `GET /api/overview` 一次聚合健康分 / SLA / 风险 / 趋势 |
| **Copilot** | 同步 `/api/chat` | `POST /api/chat/stream` SSE 实时流水线 + 降级同步 |
| **主题** | 暗色偏多、壳层不一致 | 昼夜 token 整套切换（canvas / chrome / surface / ink） |
| **语言** | 中英混杂 | 默认中文，顶栏手动切 EN；关键页面随语言切换 |
| **交互** | 静态卡片 | 健康环动效、KPI 计数、分栏可拖、会话删除/导出 |
| **版本号** | 3.1.0 | **3.2.0**（FastAPI / 前端 package / README） |

**一句话**：v3.2 不重做 Agent 内核，而是把已有 Agent + MCP + RAG + Trace + 监控，收成一张可演示、可操作的 SRE 控制台。

## 2. 控制台信息架构

```
登录
 └─ Layout（侧栏 + 顶栏）
     ├─ 运维
     │    ├─ /overview     总览（健康分 / KPI / 趋势 / 本机资源）
     │    ├─ /ops          AI 运维 Copilot（会话 + SSE 实时执行）
     │    └─ /incidents    事件（告警 + 失败 Run + 审批入口）
     ├─ 平台
     │    ├─ /infra        基础设施（Hosts / Docker / K8s）
     │    └─ /knowledge    知识中心（上传 / 预览 / RAG 检索）
     └─ 观测
          ├─ /traces       Agent 轨迹中心（Runs / 瀑布 / 步骤详情）
          └─ /monitor      监控中心（资源条 / 告警流 / Grafana /metrics）
```

旧路由兼容：`/dashboard`→`/overview`，`/chat`→`/ops`，`/servers` `/kubernetes`→`/infra`，`/monitoring`→`/monitor`，`/trace`→`/traces`。

```
    ├─ GET  /health  /metrics

LangGraph Agent / MCP / RAG / Memory / Repair
    （沿用 v3.1，本版本以前端工作台与聚合 API 为主）
```

健康分公式（写入 Overview 响应 `formula` 字段，非黑盒）：

```
health_score = 100
  - 15  (LLM 未配置)
  - 15  (DB 异常)
  - 8 × firing 告警（最多扣 40）
  - 10  (CPU > 90%)
下限 20，上限 100
time_saved_hours = 成功执行次数 × 0.25h
```

## 4. Phase 实现详情

### Phase 1 — 企业 IA 与壳层

- 侧栏三组：运维 / 平台 / 观测；品牌「企业级 AI SRE 控制台 v3.2.0」
- 顶栏：页面标题、中/EN、仅图标昼夜切换、环境徽章、未处理事件铃铛
- Copilot 全屏（隐藏重复顶栏），语言/主题开关保留在对话顶栏

### Phase 2 — Overview 总览

- 后端 `GET /api/overview`：健康分、SLA、风险、24h 执行、修复次数、节省工时、资源、趋势、事件、最近 Run
- 前端：HealthRing、KPI 计数动画、执行趋势、开放事件、本机 CPU/内存/磁盘、Agent 统计
- 加载：主接口失败则逐个兜底 `/health`、`/server/status`、`/agent/stats`；可重试，避免整页「加载失败」

### Phase 3 — Copilot + SSE

- `POST /api/chat/stream` → 前端 `streamChat()` 消费 SSE
- 右侧「实时执行」流水线：思考中 → 检索知识库 → 加载记忆 → 调用大模型 → 调用工具/MCP → 生成报告
- 危险操作审批卡：批准 / 驳回
- 失败时回退 `POST /api/chat`

### Phase 4 — 昼夜主题与对比度

语义 token：`canvas`（页底）/ `chrome`（侧栏顶栏）/ `surface`（卡片）/ `ink`（正文）

| 模式 | 页底 | 卡片 | 正文 |
|------|------|------|------|
| 夜晚 | 深蓝黑 `#0a0e17` | 抬升面，非纯白 | 近白 |
| 白天 | 浅灰 `#f1f5f9` | 白卡 | 近黑 `#0f172a` |

修复过的问题：

- 侧栏白天 + 主区黑夜撕裂
- 白天浅字叠浅底 / `pre` 黑底黑字
- Grafana 未启动时黑 iframe → 浅色占位 + `theme=light/dark`
- 头像白天近黑块 → 蓝底白字首字母

### Phase 5 — i18n（默认中文）

- `sre-locale` 默认 `zh`；顶栏「中 / EN」
- Copilot：会话、实时执行、流水线步骤
- 轨迹：运行记录、轨迹瀑布、步骤详情、用户请求/思考中/报告等
- 监控：监控中心、告警流、Grafana 占位文案

### Phase 6 — 交互增强

- 分栏拖拽：Copilot、轨迹、知识库、事件；宽度写入 localStorage；范围加大
- 会话：删除（确认后 `DELETE /api/conversations/{id}`）、导出 Markdown / JSON
- Overview 入场动效；主题按钮仅太阳/月亮图标

## 7. 已知边界（如实）

- Grafana 未 `docker compose up` 时监控页显示浅色「未启动」占位，不再嵌黑框。
- MCP stdio 仍受 `ENABLE_MCP` 与项目 2 路径控制；关闭时只用内置工具。
- 本机开发默认 SQLite；PostgreSQL / Redis / RQ 需生产 compose 才启用。
- 基础设施 Docker 页若无独立 API，引导到 Copilot 查询。

## 8. 相对 v3.1 的交付价值

1. **30 秒判断系统是否安全**：总览健康分 + SLA + 开放事件。  
2. **看得见 Agent 在干什么**：Copilot 实时流水线 + 轨迹瀑布。  
3. **能给面试/客户演示**：中文默认、昼夜一致、分栏可调、会话可导出。  
4. **不破坏 v3.1 生产能力**：Agent、MCP、RAG、审批、Helm 仍在。
